\section{What the Engine Computes and What a Certificate Must Match}\label{sec:contract}\label{sec:semantics}
A certificate is a statement about a specified computation, so ``exact'' means little until the computation is named.

\subsection{What the Engine Computes}\label{sec:stock}
The head is a matrix $W\in\BF^{V\times D}$ of $V=248{,}320$ vocabulary entries of width $D=2{,}560$, where $\BF$ denotes the BF16 numbers; row $w_i$ belongs to entry $i$. We call one head input, with the token decided from it, a \emph{position}. A decode step or a verification pass sends $M$ positions through the head in one call, and $M$ is the \emph{batch shape}. SGLang computes the head as \code{torch.matmul} of the BF16 head inputs with $W^\top$: a cuBLAS kernel, chosen by the batch shape, sums each logit's $D$ products in an FP32 \emph{accumulator} and rounds the result to BF16. The logits are widened exactly to FP32, and greedy decoding and greedy verification take \code{torch.argmax}, which returns the smallest index among equal maxima. We call this unmodified computation the \emph{stock head}, and its GEMM the \emph{stock kernel}.

\subsection{References for One Decision}\label{sec:headcontracts}
The three references below differ in where rounding enters. Let $h\in\BF^D$ be a position's head input and $z_i=\langle w_i,h\rangle$ the \emph{real logit} of entry $i$, computed in exact arithmetic over the stored operands. The stock kernel forms an FP32 accumulator $\hat y_i$ and outputs $L_i=\rnb(\hat y_i)$, where $\rnb$ rounds to the nearest BF16 value (ties to even); $\ulpb(x)$ denotes the BF16 spacing at $|x|$.

\begin{definition}[References for one decision]\label{def:contracts}
\Rreal{} returns $\min\{i:z_i=\max_jz_j\}$; \Rbf{} returns $\min\{i:\rnb(z_i)=\max_j\rnb(z_j)\}$; and \Rstock{} returns $\min\{i:L_i=\max_jL_j\}$.
\end{definition}
\Rstock{} is what an unmodified server returns. \Rbf{}, which rounds each real logit once, is not the engine's result either: the engine rounds its own FP32 sum, which can lie on the other side of a rounding boundary. An exact emulation of a kernel that adds the products one at a time in FP32 finds an example with $D=3$ on which the two choose different tokens (Appendix~\ref{app:checked}) \ev{precision}. A certified head therefore targets \Rstock{}.

\begin{lemma}[BF16 separation]\label{lem:bf16gap}
For real $y_a,y_b$, if $y_a-y_b>\ulpb(\max(|y_a|,|y_b|))$ then $\rnb(y_a)>\rnb(y_b)$.
\end{lemma}

\begin{theorem}[Gap condition]\label{thm:stock}
Let $|\hat y_i-z_i|\le G_i$ for every $i$, and let $a$ be the \Rreal{} token. If for all $b\ne a$
\begin{align*}z_a-z_b>\delta_{ab}:={}&G_a+G_b\\&+\ulpb\bigl(\max(|z_a|,|z_b|)+\max(G_a,G_b)\bigr),\end{align*}
then \Rstock{} returns $a$.
\end{theorem}
\begin{proof}
$\hat y_a-\hat y_b>\ulpb(\max(|z_a|,|z_b|)+\max(G_a,G_b))\ge\ulpb(\max(|\hat y_a|,|\hat y_b|))$, since $\ulpb$ is nondecreasing in the magnitude; Lemma~\ref{lem:bf16gap} gives $L_a>L_b$.
\end{proof}
The certified head decides with the sharper Proposition~\ref{prop:stockinterval} below and uses this theorem's margin only to screen.

\paragraph{The stock kernel's error} Theorem~\ref{thm:stock} needs a bound $G_i$ on how far the stock kernel's FP32 accumulator can lie from the real logit. The kernel is closed source and no vendor documents its rounding, so $G_i$ is an assumption. We write it as $G_i=\gamma_{\rm stock}\sum_j|w_{ij}h_j|+\eta$, where the floor $\eta=2^{-113}$ covers underflow in products and partial sums. For an entry that is never recomputed, Cauchy--Schwarz bounds $\sum_j|w_{ij}h_j|$ by $\norm{w_i}_2\norm h_2$, from row norms stored offline.

The constant $\gamma_{\rm stock}$ comes from one of two named \emph{error models}. The \emph{\modelcons} charges $2D$ roundings of relative size $2^{-23}$ in any order, $\gamma_{\rm stock}=\gcons$. It covers any summation order, split-$K$ (a sum divided among thread blocks) with FP32 partial sums, and truncating adders that keep at least 23 fractional bits per block of addends (the published Hopper model keeps 25). The \emph{\modelhopper}, $\gamma_{\rm stock}=\ghop$, starts from Khattak and Mikaitis's measurement-based model of BF16 tensor-core arithmetic on Hopper, the GH200's GPU architecture~\cite{khattak2026}, and adds an allowance for FP32 split-$K$. Khattak and Mikaitis measured that arithmetic through the warp-level \code{mma} instructions, not the warpgroup \code{wgmma} instruction. Neither model is a vendor contract. Neither covers split-$K$ partial sums stored in BF16, which PyTorch permits by default~\cite{torchnumeric}; on this build, forbidding them changes neither the selected kernel nor any output bit \ev{kernel-error}.

\paragraph{A screen needs a margin} A screen sees only an interval $lo_i\le z_i\le hi_i$ for each entry, and it must not drop any entry that could still be the stock token, including entries it never recomputes. An entry that loses in real arithmetic can still tie or win after the stock kernel's error and rounding, so an upper end below the largest lower end is not enough to drop it. Let $G_{\max}=\max_iG_i$ and let $\bar z=\max_i\max(|lo_i|,|hi_i|)$ be the largest magnitude any interval reaches. Then $\delta_{\max}=2G_{\max}+\ulpb(\bar z+G_{\max})$ is at least $\delta_{ab}$ of Theorem~\ref{thm:stock} for every pair, so, given valid intervals, an entry with $hi_j<\max_ilo_i-\delta_{\max}$ can be dropped for good (Figure~\ref{fig:mechanism}a).

\subsection{The Interval Condition and the Fallback}\label{sec:kernel-fallback}
The gap condition demands a margin of more than one BF16 spacing even when $G$ is negligible, which a few percent of positions lack (Table~\ref{tab:fallback}). The rounding boundaries can be used exactly instead. Rounding is monotone, so an interval $[\hat y_i^-,\hat y_i^+]$ that contains entry $i$'s accumulator puts $L_i$ in $[L_i^-,L_i^+]=[\rnb(\hat y_i^-),\rnb(\hat y_i^+)]$ (Figure~\ref{fig:mechanism}b).

\begin{proposition}[Interval condition]\label{prop:stockinterval}
Let $C$ be a set of entries such that every $j\notin C$ has $L_j^+<\max_{i\in C}L_i^-$, and let $k=\min\{i\in C:L_i^-=\max_{j\in C}L_j^-\}$. If $L_j^+<L_k^-$ for every $j\in C$ with $j<k$, and $L_j^+\le L_k^-$ for every $j\in C$ with $j>k$, then \Rstock{} returns $k$.
\end{proposition}
\begin{proof}
For $j<k$ in $C$, $L_j\le L_j^+<L_k^-\le L_k$; for $j>k$ in $C$, $L_j\le L_j^+\le L_k^-\le L_k$, so a later index can at most tie and the first-index rule returns $k$; entries outside $C$ satisfy $L_j<L_k^-\le L_k$.
\end{proof}
Two entries whose logits round to the same BF16 value under every accumulation the error model admits are thus certified as tied, and the lower index wins; only a tie that the accumulation error could make or unmake stays open.

\paragraph{The contract and the fallback} A certified head promises \Rstock{} at the batch shape it serves. It certifies a position only when Proposition~\ref{prop:stockinterval} fixes that token for every accumulator value the named error model admits, and sends every other position to a fallback that runs the stock head. The \emph{whole-batch fallback} reruns the same \code{torch.matmul} on the whole batch at the same $M$, so cuBLAS selects the same kernel. It needs no error model, but one undecided position makes the whole batch pay. The \emph{per-position fallback} finishes one undecided position with a stock \code{matmul} over its gathered candidate entries; it applies only to a position left open by a near tie whose candidate list is complete and has at most 64 entries (Section~\ref{sec:kernel-design}). It is exact only if a position's BF16 logits stay the same when the rest of the batch, or the set of entries computed, changes. In principle cuBLAS may choose another kernel, and so another summation order, for each batch shape; on this build a position's logits were bitwise the same at 20 batch sizes from 1 to 256, with all entries or only gathered ones computed, and a start-up self-test re-checks the gathered case at the deployed batch sizes \ev{kernel-invariance}. Nothing guarantees that for other shapes or builds, so the contract still fixes $M$. Either fallback is a conditional node of the recorded CUDA graph, paid only when it runs.
