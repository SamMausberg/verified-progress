\section{What the Engine Computes and What a Certificate Must Match}\label{sec:contract}\label{sec:semantics}
The reference for a certified head is the token the unmodified engine serves at the same batch shape, not the argmax of exact or once-rounded logits, which can differ because the engine rounds its own FP32 sums. A certificate must therefore show that every set of FP32 sums the stock kernel could form within an assumed error bound rounds to BF16 logits with the same first maximal index.

\subsection{What the Engine Computes}\label{sec:stock}
The head is a matrix $W\in\BF^{V\times D}$ of $V=248{,}320$ vocabulary entries of width $D=2{,}560$, where $\BF$ denotes the BF16 numbers; row $w_i$ belongs to entry $i$. We call one head input $h\in\BF^D$, with the token decided from it, a \emph{position}. The \emph{batch shape} $M$ is the number of positions in one head call, from a decode step or a verification pass. SGLang computes the head as \code{torch.matmul} of the BF16 head inputs with $W^\top$: a cuBLAS kernel, chosen by the batch shape, sums each logit's $D$ products in an FP32 running sum, the \emph{accumulator} $\hat y_i$, and outputs $L_i=\rnb(\hat y_i)$, where $\rnb$ rounds to the nearest BF16 value (ties to even). The logits are widened exactly to FP32, and greedy decoding and verification take \code{torch.argmax}, which returns the smallest index among equal maxima. This unmodified computation is the \emph{stock head}, and its GEMM the \emph{stock kernel}.

\subsection{References for One Decision}\label{sec:headcontracts}
Let $z_i=\langle w_i,h\rangle$ be the \emph{real logit} of entry $i$, computed exactly from the stored operands, and $\ulpb(x)$ the BF16 spacing at $|x|$. The references take the first maximal index of the real logits, their BF16 roundings or the stock kernel's outputs.

\begin{definition}[References for one decision]\label{def:contracts}
\Rreal{} returns $\min\{i:z_i=\max_jz_j\}$; \Rbf{} returns $\min\{i:\rnb(z_i)=\max_j\rnb(z_j)\}$; and \Rstock{} returns $\min\{i:L_i=\max_jL_j\}$.
\end{definition}
An exact emulation of a sequential FP32 kernel finds a \mbox{$D=3$} example where \Rbf{} and \Rstock{} differ (Appendix~\ref{app:contracts}) \ev{precision}.

\begin{lemma}[BF16 separation]\label{lem:bf16gap}
For real $y_a,y_b$, if $y_a-y_b>\ulpb(\max(|y_a|,|y_b|))$ then $\rnb(y_a)>\rnb(y_b)$.
\end{lemma}

\begin{theorem}[Gap condition; proof in Appendix~\ref{app:bf16gap}]\label{thm:stock}
Let $|\hat y_i-z_i|\le G_i$ for every $i$, and let $a$ be the \Rreal{} token. If for all $b\ne a$
\begin{align*}z_a-z_b>\delta_{ab}:={}&G_a+G_b\\&+\ulpb\bigl(\max(|z_a|,|z_b|)+\max(G_a,G_b)\bigr),\end{align*}
then \Rstock{} returns $a$.
\end{theorem}

\paragraph{The stock kernel's error} Theorem~\ref{thm:stock} needs a bound $G_i$ on the stock kernel's error $|\hat y_i-z_i|$, which for a closed-source kernel can only be assumed. We write it as $G_i=\gamma_{\rm stock}\sum_j|w_{ij}h_j|+\eta$, where the floor $\eta=2^{-113}$ covers underflow in products and partial sums. Entries never recomputed use $\sum_j|w_{ij}h_j|\le\norm{w_i}_2\norm h_2$ (Cauchy--Schwarz).

An \emph{error model} fixes $\gamma_{\rm stock}$; we name two. The \emph{\modelcons} charges $2D$ roundings of relative size $2^{-23}$ in any order, $\gamma_{\rm stock}=\gcons$; this covers split-$K$ (a sum divided among thread blocks) with FP32 partial sums and truncating adders that keep at least 23 fractional bits per block of 8 to 32 addends. The \emph{\modelhopper}, $\gamma_{\rm stock}=\ghop$, adds an allowance for FP32 split-$K$ to Khattak and Mikaitis's measurement-based model of BF16 tensor cores on Hopper, the GH200's GPU architecture~\cite{khattak2026}: blocks of 16 products, 25 fractional bits, and truncation of the dropped bits and of the sum. They measured warp-level \code{mma} instructions; the two stock head kernels we inspected ($M=1$ and 32) issue warpgroup \code{wgmma}, but on crafted inputs all fourteen kernels cuBLAS selects for $M=1$ to 256 accumulate this way, on one GPU \ev{profile-wgmma}. Neither model is a vendor contract. The stock GEMM's FP32-output variant, a separate kernel whose accumulator can be read, showed a largest error of about 1/58 of the \modelhopper's bound \ev{kernel-error}. Neither model covers split-$K$ partial sums stored in BF16, which PyTorch permits by default~\cite{torchnumeric}; on this build, forbidding them changes neither the selected kernel nor any output bit \ev{kernel-error}.

\paragraph{A screen needs a margin} A \emph{screen} drops, without recomputing them, entries whose intervals $\lo_i\le z_i\le \hi_i$ show they cannot be the stock token. An entry that loses in real arithmetic can still tie or win after the stock kernel's error and rounding. With $G_{\max}=\max_iG_i$ and $\bar z=\max_i\max(|\lo_i|,|\hi_i|)$, the largest interval magnitude, the margin $\delta_{\max}=2G_{\max}+\ulpb(\bar z+G_{\max})$ is at least every pair's $\delta_{ab}$, so, given valid intervals, an entry with $\hi_j<\max_i\lo_i-\delta_{\max}$ can be dropped for good (Figure~\ref{fig:mechanism}a).

\subsection{The Interval Condition and the Fallback}\label{sec:kernel-fallback}
The gap condition needs a margin above one BF16 spacing even for negligible $G$, which a few percent of positions lack (Table~\ref{tab:fallback}); the interval condition uses the rounding boundaries exactly. Rounding is monotone, so an interval $[\hat y_i^-,\hat y_i^+]$ that contains entry $i$'s accumulator puts $L_i$ in $[L_i^-,L_i^+]=[\rnb(\hat y_i^-),\rnb(\hat y_i^+)]$ (Figure~\ref{fig:mechanism}b).

\begin{proposition}[Interval condition]\label{prop:stockinterval}
Let $C$ be a set of entries such that every $j\notin C$ has $L_j^+<\max_{i\in C}L_i^-$, and let $k=\min\{i\in C:L_i^-=\max_{j\in C}L_j^-\}$. If $L_j^+<L_k^-$ for every $j\in C$ with $j<k$, and $L_j^+\le L_k^-$ for every $j\in C$ with $j>k$, then \Rstock{} returns $k$.
\end{proposition}
\begin{proof}
For $j<k$ in $C$, $L_j\le L_j^+<L_k^-\le L_k$; for $j>k$ in $C$, $L_j\le L_j^+\le L_k^-\le L_k$, so a later index can at most tie and the first-index rule returns $k$; entries outside $C$ satisfy $L_j<L_k^-\le L_k$.
\end{proof}
A BF16 tie that holds under every admissible accumulation is certified, and the lower index wins; only a tie the accumulation error could make or unmake stays open.

\paragraph{The contract and the fallback} A position is \emph{certified} when Proposition~\ref{prop:stockinterval} fixes its \Rstock{} token for every accumulator value the error model admits; any other position runs the stock head in a fallback, a conditional node of the CUDA graph, paid only when it runs. The \emph{whole-batch fallback} reruns \code{torch.matmul} on the whole batch at the same $M$, so cuBLAS selects the same kernel; it needs no error model, but one undecided position makes the whole batch pay. The \emph{per-position fallback} serves a position left open by a near tie whose candidate list is complete and has at most 64 entries (Section~\ref{sec:kernel-design}), with a stock \code{matmul} over its gathered candidates. It is exact only if a position's BF16 logits depend neither on the rest of the batch nor on which entries are computed. cuBLAS may choose a different kernel, and summation order, per batch shape; on this build a position's logits were bitwise the same at 20 batch sizes from 1 to 256, with all entries or only gathered ones computed, and a start-up self-test re-checks the gathered case at the deployed batch sizes \ev{kernel-invariance}. Nothing guarantees that for other shapes or builds, so the contract still fixes $M$.
