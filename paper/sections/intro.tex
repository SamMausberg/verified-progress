\section{Introduction}\label{sec:intro}\label{sec:question}
In speculative decoding a cheap drafter proposes several tokens and the target model checks them all in one forward pass~\cite{specdecode,chen2023specsampling}. At each checked position the target multiplies its final hidden state, the \emph{head input}, by the output head, which gives a score (logit) for every vocabulary entry. A greedy verifier uses one fact from those scores, which entry is largest, and accepts a drafted token if and only if it is that entry. Plain greedy decoding makes the same single use of the head. Any shortcut through the head must therefore return exactly that token, and this paper's core is what ``exactly'' has to mean inside a production engine.

The speed at stake is modest. For Qwen3.5-4B the head has 248,320 entries; in BF16 it is 15\% of the weights a plain decode step reads (Table~\ref{tab:bytes}). On a GH200 at batch 1 it takes 10.3\% of a plain decode step \ev{profile-head}, so even a free head would speed up such a step by only about 11\%. In a speculative cycle with the model's multi-token-prediction drafter (MTP-4B below), the target's verification head takes 4.4\% \ev{profile-attr} (Figure~\ref{fig:breakdown}). Drafters that project through the same head spend more there, 12.9\% of that cycle and, in other work, 49\% of an EAGLE-2 drafter's time~\cite{frspec}. A certified head could serve those projections too; matching the stock token there keeps the drafts, and so the acceptance rate, unchanged, though the output's correctness does not depend on it.

Most of the head's computation goes to entries that cannot win, and it can be skipped by bounding instead of computing (Figure~\ref{fig:mechanism}). First, approximate every score cheaply, here from an int8 copy of the head, which reads half the bytes. Second, bound each approximation's error, so that every entry gets an interval guaranteed to contain its exact score. Third, discard every entry whose interval cannot reach the leader's, and recompute the few that remain exactly. Fourth, when the bounds still cannot single out the winner, fall back to the full computation. This pays when the intervals are narrow compared with the gap between the two best scores, as they are on this model (Section~\ref{sec:candidates}). Public implementations already screen greedy heads this way: sparkpipe certifies against exact arithmetic with a bound for CUDA-core accumulation~\cite{sparkpipehead}, dgpp takes the quantized head as its reference~\cite{dgpphead}, a Metal implementation recomputes with a replica of the stock kernel~\cite{lagunaprune}, and knlp reports how often its argmax matches~\cite{knlphead}; exact sampling from bounded scores is older~\cite{astar,mussmann2017}. A production engine's head kernel is closed source, so no replica exists. What is new here is a certificate for that kernel's token based on a model of its error, a bound that holds for tensor-core accumulation, and the extension to seeded sampling (Section~\ref{sec:related}).

The hard part is deciding what the cheap computation must agree with, because the engine does not compute exact scores. It sums each logit in FP32, in an order its kernel chooses, rounds the sum to BF16, and returns the first index among equal maxima. BF16 keeps eight significant bits, so logits between 16 and 32 are 0.125 apart. In a hypothetical case, logits of 20.02 and 20.05 both round to 20.0. The engine then returns whichever entry has the lower index, even if its exact score is the smaller. On this model the engine's two largest logits tie in BF16 at 1.0\% of greedy positions, and the exact-arithmetic winner differs from the engine's token at about 0.5\% \ev{alignment}.

We therefore take the engine's own head as the reference: a certified head must return the token the unmodified (stock) head returns for the same head input at the same batch shape. That makes it a drop-in replacement whose correctness can be tested by bit-equality against the unmodified engine in the same configuration. We prove when intervals around the stock kernel's FP32 sums, before rounding, fix that token (Section~\ref{sec:contract}). The proof needs a bound on the kernel's rounding error, which no vendor documents, so we assume one under two named error models and test it. Positions the intervals cannot decide run the stock head, so a failed certificate costs time, not agreement; a certified token can be wrong only if an assumption of Table~\ref{tab:assumptions} fails.

We also test a second source of bounds, which we call \emph{transport}. A drafter that projects through the same head, such as MTP-4B or the public DFlash block drafter for this model (DFlash-4B), computes every logit at its own head input, and summaries of them per tile of 64 entries (the largest score and the sum of exponentiated scores) would cost little more. A Cauchy--Schwarz bound can carry those summaries to the target's head input, so the verifier would reuse work already paid for. The head's weights imply that this beats the int8 copy only if draft and target head inputs agree to about one part in a hundred. They differ by a median 92\% for DFlash-4B and 95\% for MTP-4B, and the certificates skip almost nothing.

\subsection{Contributions}\label{sec:contributions}
\begin{enumerate}[leftmargin=1.2em,itemsep=.3ex]
\item \emph{A contract against the engine's own head} (Section~\ref{sec:contract}): proved conditions under which intervals around the stock kernel's FP32 sums fix the stock head's token at the same batch shape, with the stock head as the fallback. The kernel's error bound is assumed and tested, not proved.
\item \emph{A certified head that meets it} (Section~\ref{sec:head}): an error bound for the int8 copy that holds for tensor-core accumulation, a five-step decision, and the same decision for SGLang's seeded sampler. Each compiled kernel is checked, not proved, to compute the modelled arithmetic.
\item \emph{Measurements on the engine's own states} (Section~\ref{sec:measure}): recomputation, fallback and token agreement offline and inside the engine, and the head's time in isolation; the effect on serving is not yet measured \pend{bench-cert}.
\item \emph{A negative result} (Section~\ref{sec:transport}): for both public drafters and every bound variant and tile layout tested, certified transport skips under 0.7\% of the vocabulary.
\end{enumerate}
