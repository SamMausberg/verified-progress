\section{Introduction}\label{sec:intro}\label{sec:question}
In speculative decoding a cheap drafter proposes several tokens and the target model checks them all in one forward pass~\cite{specdecode,chen2023specsampling}. At each checked position the target multiplies its final hidden state, the \emph{head input}, by the output head, which gives a score (logit) for every vocabulary entry. A greedy verifier uses one fact from those scores, which entry is largest, and accepts a drafted token if and only if it is that entry; a seeded sampling verifier uses the largest score after fixed random noise is added (Section~\ref{sec:decisions}). Plain greedy decoding makes the same single use of the head. For Qwen3.5-4B the head has 248,320 entries and occupies 1.27~GB in BF16, 15\% of the weights a plain decode step reads (Table~\ref{tab:bytes}). On a GH200, at batch 1, it takes 10.3\% of a plain decode step and 17.2\% of a speculative cycle with the model's multi-token-prediction (MTP) drafter \ev{profile-head} (Figure~\ref{fig:breakdown}), so even a free head would speed up a plain step at batch 1 by only about 11\%. The question here is narrower than speed: how much of the head's computation a verifier needs, and what a cheaper computation must agree with inside a production engine.

Most of that computation goes to entries that cannot win, and it can be skipped by bounding instead of computing (Figure~\ref{fig:mechanism}). First, approximate every score cheaply, here from an int8 copy of the head, which reads half the bytes. Second, bound each approximation's error, so that every entry gets an interval guaranteed to contain its exact score. Third, discard every entry whose interval cannot reach the leader's, and recompute the few that remain exactly. Fourth, when the bounds still cannot single out the winner, fall back to the full computation. Public implementations screen and refine greedy heads in this way~\cite{sparkpipehead,dgpphead,lagunaprune,knlphead}, and exact sampling from bounded scores is older~\cite{astar,mussmann2017}. It pays when the bounds are narrow compared with the gap between the two best scores; on the states we captured, the int8 intervals are about one logit wide and the median gap is 7.3 logits \ev{stats}.

The hard part is deciding what the cheap computation must agree with, because the engine does not compute exact scores. It sums each logit in FP32, in an order its kernel chooses, rounds the sum to BF16, and returns the first index among equal maxima. BF16 keeps eight significant bits, so logits between 16 and 32 are 0.125 apart. In a hypothetical case, logits of 20.02 and 20.05 both round to 20.0, and the engine returns whichever entry has the lower index, even if its exact score is the smaller. On this model the engine's two largest logits tie in BF16 at 1.0\% of greedy positions, and the exact-arithmetic winner differs from the engine's token at about 0.5\% \ev{alignment}. A certificate for the exact winner certifies a computation the engine does not perform.

We therefore take the engine's own kernel as the reference: a certified head must return the token the stock head kernel returns for the same head input at the same batch shape. We prove when intervals around the kernel's FP32 sums, before rounding, fix that token (Section~\ref{sec:contract}). The proof needs a bound on the kernel's rounding error, which no vendor documents, so we assume one under two named error models and test it. Positions the intervals cannot decide run the stock kernel, so a failed certificate costs time, not agreement; a certified token can be wrong only if an assumption of Table~\ref{tab:assumptions} fails.

We also test \emph{transport}, the mechanism this work set out to build. A drafter that projects through the same head has already computed, for each tile of 64 consecutive vocabulary entries, the largest score and the sum of exponentiated scores; a Cauchy--Schwarz bound can carry these summaries to the target's head input, so the verifier would reuse work already paid for. That beats the int8 copy only if draft and target head inputs agree to about one part in a hundred. On real states they differ by a median 92\% for the public DFlash drafter and 95\% for the MTP layer, and the certificates skip almost nothing.

\subsection{Contributions}\label{sec:contributions}
\begin{enumerate}[leftmargin=1.2em,itemsep=.3ex]
\item \emph{A contract against the engine's own kernel} (Section~\ref{sec:contract}): two proved conditions under which intervals around the stock kernel's FP32 sums fix its token at the same batch shape, with that kernel as the fallback. The kernel's error bound is assumed and tested, not proved.
\item \emph{A certified head that meets it} (Section~\ref{sec:head}): an error bound for the int8 copy that holds for tensor-core accumulation under Khattak and Mikaitis's model of Hopper~\cite{khattak2026}, and one refinement procedure for greedy decoding and, against the engine's deterministic-inference mode without truncation, for seeded sampling and fixed-noise verification. A kernel inherits the bound only if it computes the modelled arithmetic, which is checked per compiled variant, not proved. The greedy form is prior art (Section~\ref{sec:related}).
\item \emph{Measurements on the engine's own states} (Section~\ref{sec:measure}): candidates, fallback shares and token agreement on captured positions, and the head's runtime in isolation \ev{kernel-path}; the effect on serving is \pend{bench-cert}.
\item \emph{A negative result with its cause} (Section~\ref{sec:transport}): for both public drafters the head inputs differ two orders of magnitude more than transport tolerates, and in every bound family and tiling tested certified transport skips at most 0.65\% of the vocabulary.
\end{enumerate}
