\section{Introduction}\label{sec:intro}\label{sec:question}
In speculative decoding a cheap drafter proposes several tokens and the target model checks them all in one forward pass~\cite{specdecode,chen2023specsampling}. At each checked position the target multiplies its final hidden state, the \emph{head input}, by the output head, which gives a score (logit) for every vocabulary entry. A greedy verifier uses one fact from those scores, which entry is largest, and accepts a drafted token if and only if it is that entry; a seeded sampling verifier uses the largest score after fixed random noise is added (Section~\ref{sec:decisions}). Plain greedy decoding makes the same single use of the head. For Qwen3.5-4B the head, tied to the input embedding, has 248,320 entries of width 2,560: 1.27~GB in BF16, 15\% of the weight bytes of a plain decode step and 84\% of those of a multi-token-prediction (MTP) draft step (derived from the checkpoint, Table~\ref{tab:bytes}). Measured on a GH200, the head's matrix multiply, FP32 copy and argmax take 10.3\% of a plain decode step at batch 1, 6.1\% at batch 128, and 17.2\% of an MTP speculative cycle at batch 1 \ev{profile-head} (Figure~\ref{fig:breakdown}), so even a free head would speed up a plain step at batch 1 by only about 11\%. The question here is narrower than speed: how much of the head's computation a verifier needs, and what a cheaper computation must agree with inside a production engine.

Most of that computation goes to entries that cannot win, and it can be skipped by bounding instead of computing (Figure~\ref{fig:mechanism}). First, approximate every score cheaply, here from an int8 copy of the head, which reads half the bytes. Second, bound each approximation's error, so that every entry gets an interval guaranteed to contain its exact score. Third, discard every entry whose interval cannot reach the leader's, and recompute the few that remain exactly. Fourth, when the bounds still cannot single out the winner, fall back to the full computation. Public implementations screen and refine greedy heads in this way~\cite{sparkpipehead,dgpphead,lagunaprune,knlphead}, and exact sampling from bounded scores is older~\cite{astar,mussmann2017}. It pays when the bounds are narrow compared with the gap between the two best scores; on the states we captured, the int8 intervals are about one logit wide and the median gap is 7.3 logits \ev{stats}.

The hard part is deciding what the cheap computation must agree with, because the engine does not compute exact scores. It sums each logit in FP32, in an order its kernel chooses, rounds the sum to BF16, and returns the first index among equal maxima. BF16 keeps eight significant bits, so logits between 16 and 32 are 0.125 apart. In a hypothetical case, logits of 20.02 and 20.05 both round to 20.0, and the engine returns whichever entry has the lower index, even if its exact score is the smaller. On this model the engine's two largest logits tie in BF16 at 1.0\% of greedy positions, and the exact-arithmetic winner differs from the engine's token at about 0.5\% \ev{alignment}. A certificate for the exact winner certifies a computation the engine does not perform.

We therefore take the engine's own kernel as the reference: a certified head must return the token the stock head kernel returns for the same head input at the same batch shape, rounding and tie rule included. We prove when intervals that contain the kernel's FP32 sums, before rounding, fix that token (Section~\ref{sec:contract}). The proof needs a bound on the kernel's rounding error, which no vendor documents, so we assume one under two named error models and test it. Every position the intervals cannot decide runs the stock kernel, so a failed certificate costs time, never agreement; a certified token can be wrong only if an assumption of Table~\ref{tab:assumptions} fails.

We also test \emph{transport}, the mechanism this work set out to build. A drafter that projects through the same head has already computed, for each tile of 64 consecutive vocabulary entries, the largest score and the sum of exponentiated scores, and a Cauchy--Schwarz bound can carry these summaries to the target's head input, so the verifier would reuse work already paid for. The head's weights say this beats the int8 copy only if draft and target head inputs agree to about one part in a hundred. On real states they differ by a median 92\% for the public DFlash drafter and 95\% for the model's own MTP layer, and the certificates skip almost nothing.

\subsection{Contributions}\label{sec:contributions}
\begin{enumerate}[leftmargin=1.2em,itemsep=.3ex]
\item \emph{A contract against the engine's own kernel} (Section~\ref{sec:contract}): a gap condition and a sharper interval form, both proved, say when intervals around the stock kernel's FP32 sums fix its token at the same batch shape, with that kernel as the fallback. Its error bound is assumed and tested, not proved (Table~\ref{tab:assumptions}).
\item \emph{A certified head that meets it} (Section~\ref{sec:head}): an error bound for the int8 copy that holds for tensor-core accumulation under Khattak and Mikaitis's model of Hopper~\cite{khattak2026}, or with no model for an integer pass, and one refinement for greedy selection, seeded sampling and fixed-noise verification, the last two against the engine's deterministic-inference mode (proved, and matched on 60,000 replayed positions \ev{kernel-seeded}). A kernel inherits the bound only if it computes the modelled arithmetic, which is checked per compiled variant, not proved. The greedy form is prior art (Section~\ref{sec:related}).
\item \emph{Measurements on the engine's own states} (Section~\ref{sec:measure}): candidates, fallback shares under both error models and token agreement on 6,005 captured plain-decoding positions, and the head-only runtime \ev{kernel-path}; the effect on serving is \pend{bench-cert}.
\item \emph{A negative result with its cause} (Section~\ref{sec:transport}): for both public drafters the head inputs differ two orders of magnitude more than transport tolerates, and certified transport skips at most 0.65\% of the vocabulary, no more than a static screen that ignores the draft.
\end{enumerate}
