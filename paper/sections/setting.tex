\section{Setting}\label{sec:setting}
\subsection{Model, engine and machine}\label{sec:setting-model}
The target is Qwen3.5-4B at revision \modelpin~\cite{qwenconfig,qwencard}. Its configuration gives hidden width 2,560, a vocabulary of 248,320 and 32 decoder layers, of which 24 use Gated DeltaNet (GDN) linear attention~\cite{gdn} and 8, every fourth, use full attention. It has one native multi-token-prediction (MTP) layer, and its output head is tied to the input embedding. The checkpoint is multimodal; the engine loads its vision tower, but every experiment here is text-only and never reaches it.

Table~\ref{tab:bytes} gives the byte counts that frame the rest of the paper. They are derived from the checkpoint's tensor sizes and the configuration, not measured. A plain decode step streams every decoder weight once plus the whole head, while the embedding lookup reads one row per request, so the head is 15.1\% of the weight bytes of a plain step. An MTP draft step runs one small layer followed by the same head, so there the head is 84.1\% of the weight bytes. The recurrent state is per request. The configuration stores it in FP32 (\code{mamba\_ssm\_dtype}), so each request holds $24\times32\times128\times128\times4$ bytes $=50.3$~MB of GDN state, and a decode kernel that reads and writes it once per step moves 100.7~MB per request per step, which equals the weight bytes of a step at a batch of 84 requests. Section~\ref{sec:stack} builds on these counts.

The engine is SGLang at commit \sourcepin~\cite{sglangpaper}, with CUDA graphs and the overlap scheduler on and the FlashInfer attention backend~\cite{flashinfer}; FlashAttention~3 is not available on this aarch64 host. The machine is one NVIDIA GH200 with 96~GB of HBM3 (compute capability 9.0) and a 64-core Grace CPU. Two drafters are in scope. The native MTP layer is served through SGLang's \code{NEXTN} path, which the engine reports as EAGLE~\cite{eagle}. The public DFlash block drafter for this exact target, \code{z-lab/Qwen3.5-4B-DFlash}~\cite{dflashpaper,dflash4bcard}, has six layers, drafts blocks of up to 16 tokens conditioned on eight of the target's intermediate hidden states, and has no head of its own: its drafts are projected through the target's tied head. It is therefore both the strongest public speculative baseline for this model and a direct test bed for transport. The public DFlash~2 pair for Qwen3.8-27B~\cite{dflash,dflashcard} is a transfer lane; no DFlash~2 checkpoint for the 4B model is public.

\subsection{What the stock engine computes}\label{sec:stock}
At the pinned commit, with the defaults used here, the head is \code{torch.matmul(h.to(bf16), W.T)} in \code{LogitsProcessor.\_compute\_lm\_head} (\path{python/sglang/srt/layers/logits_processor.py}). The product is a cuBLAS BF16 GEMM that accumulates in FP32 and returns BF16 logits, which are then copied into an FP32 buffer. cuBLAS chooses its algorithm per shape, so the logits of a row can depend on how many rows are in the batch, and PyTorch's default permits reduced-precision reductions in BF16 GEMMs. Greedy decoding and greedy verification take \code{torch.argmax}, which returns the first maximal index. BF16 keeps eight significant bits, so logits in $[16,32)$ are spaced $0.125$ apart; two real logits closer than about one spacing can round to the same BF16 value, and then the smaller token index wins.

Sampling at the pin is already a race. Without top-$k$, top-$p$ or min-$p$ and without a seed, the sampler returns $\argmax_i p_i/E_i$ with $E_i$ exponential draws from the Philox generator, which is Gumbel-max in another form (\code{SGLANG\_OPT\_USE\_GUMBEL\_SAMPLE}, on by default). With a per-request seed it returns $\argmax_i(\log p_i+G_i)$ in FP64, where $G_i=-\log(-\log x_i)$ and $x_i$ is a 32-bit MurmurHash of (seed, position, token) scaled to $[0,1]$ (\code{multinomial\_with\_seed} in \path{python/sglang/srt/layers/sampler.py}). That is a counter-based noise field: the noise of any token can be recomputed on its own, in any order. Sampled speculative verification by default uses point-mass drafts: a drafted token is accepted when a uniform coin falls below the target probability mass of the siblings tried so far, and a rejection samples the target restricted to the untried tokens by inverse CDF. Two flags change the reference. \code{-{}-enable-fp32-lm-head} makes the head return FP32 logits, and \code{-{}-enable-deterministic-inference} replaces the default matrix multiplication with a persistent batch-invariant Triton kernel~\cite{sglangdeterministic}.

\subsection{Replaying the head inputs the engine used}\label{sec:transport-capture}
Every measurement of a head certificate in this paper replays vectors the engine actually fed to its head. The serving engine does not expose them, so a capture-only patch (\path{engine/sglang/patches/geometry/0001-head-capture-replay-dumps.patch}) stashes the tensor \code{LogitsProcessor} hands to the head and joins it, inside the same step, with the tokens the engine chose; for speculation it also records the proposed tokens, the target's argmax and the accepted lengths. Hidden vectors are stored as BF16 bit patterns, so the replay reads exactly what the head read. The hooks run in Python between forwards, so the capture server runs without CUDA graphs and without the overlap scheduler; it is a correctness configuration, not a performance one. The prompts are 320 public prompts, split by prompt into analysis and held-out halves before any fitting, decoded greedily for 384 new tokens.

For speculation the pairing follows the verify layout. A verify step for one request holds $[x_0,d_1,\dots,d_S]$ with $x_0$ the last committed token; draft token $d_k$ came from the draft input $h^d_k$ and is decided by the target input at verify position $k-1$. Each pair is labelled accepted, rejected or unreached. The target input at the last verify position, which produces the bonus token, has no draft anchor at all, so a transport-only verifier still streams the whole head for that row.

The capture was checked by recomputation rather than assumed correct. In plain decoding the FP64 argmax of the captured head input equals the engine's token at 99.51\% of 105,269 positions, and all 519 disagreements lie within one BF16 spacing of the FP64 winner (the largest gap is 0.118 logits where the spacing is 0.125). The argmax of the exact logits rounded to BF16, with the first-index rule, matches the engine at 99.998\%; that rule is not the engine's computation (Section~\ref{sec:headcontracts}), and the few remaining positions are where the two differ. The engine's own top two logits were equal in BF16 at 1.0\% of positions, where the stock decision is set by the tie rule. The real-arithmetic winner and the stock token therefore differ at about 0.5\% of greedy positions here~\ev{alignment}. That gap is the reason Section~\ref{sec:semantics} names the stock kernel, not real arithmetic, as the reference.
